# YANDI desktop · P2 M3

Нативная Linux-оболочка существующего демона, без WebView и собственного хранилища данных.
Первичная настройка, локальный вход по uid, панель, контакты по карточке узла, текстовый чат, профиль, пароль входа и закрытая среда. Группы: список, каталог, создание, приглашения, участники, роли, правила и текстовая переписка. Шлюзы: CRUD, HTTP/SOCKS5; Relay: сервер, сессии и подключение. Звонки: единый координатор и сигналы узлов/телефонов, с подставным медиа-интерфейсом. Файлы и настоящее WebRTC ещё не реализованы; веб-UI сохранён.

## Запуск

```bash
./build/linux/x64/debug/bundle/yandi_desktop
./build/linux/x64/debug/bundle/yandi_desktop --socket /absolute/test/data/run/yandi-ui.sock
```

Приоритет: `--socket PATH` / `--socket=PATH`, затем `YANDI_UI_SOCKET`, затем `$XDG_DATA_HOME/yandi/run/yandi-ui.sock` или `$HOME/.local/share/yandi/run/yandi-ui.sock`.
Не указывайте URL вместо пути. Сокет и демон должны принадлежать вашему пользователю. Без демона окно показывает «Нет связи с демоном»; интернет оболочке не требуется.

На Unix-сокете браузерный пароль/cookie не требуются: владелец допускается демоном по uid. «Войти» открывает локальную панель; пароль закрытой среды вводится отдельно. Перепривязка identity выполняется существующим `yandi-keys recover`, а форма восстановления пароля использует `/api/auth/recover`.

## Проверка с настоящим демоном

Из корня репозитория:

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u all_proxy nice -n 15 python3 chaos/desktop_shell_m1.py /absolute/path/to/current/yandi
```

Нужны `unshare`, `mount`, `ip`, доступные user namespaces и текущий бинарь с исправлением Unix WebSocket из M3. Скрипт создаёт отдельные user/network/mount namespaces и tmpfs `/tmp`, поднимает только loopback, задаёт временные HOME/XDG через существующий лабораторный Node и запускает тот же Dart UnixApi. Проверяет setup, status/nodes/speed, vault setup/lock/unlock/change/recover/auto-lock, HTTP 501 и запертое состояние после рестарта. Дополнительно второй временный узел проверяет импорт карточек, CRUD контактов, чат в обе стороны и профиль через общий ShellRepository и UnixApi. Временные данные удаляются. Это RPC-интеграция; GTK-формы с настоящим демоном вручную отдельно.
Не запускайте `tool/daemon_probe.dart`, `tool/chat_probe.dart`, `tool/network_probe.dart` и `tool/call_probe.dart` на сокете владельца: он меняет тестовые пароли и настройки.

## Память и границы

Нет хранения паролей, cookies, токенов, истории, настроек или API-ответов на диске. GPU shader disk cache отключён в runner; GTK settings backend — memory. Секретные поля скрыты, без автодополнения, подсказок и персонализации IME. Контроллеры очищаются при отправке, скрытии, выходе и блокировке. UTF-8 копии и буфер запроса зануляются, ответ ограничен 1 МиБ и его byte buffer также зануляется. Dart/Flutter editing, JSON и системный IME используют неизменяемые String и внутренние копии, физическое стирание всей памяти не гарантируется. ОС может иметь swap/core dumps, debug-сборка имеет VM service; это не сборка для распространения.

Опрос vault — 1 с, status — 5 с, speed — 2 с, nodes — 10 с, без наложения циклов. При скрытии/потере фокуса отменяются запросы, очищаются формы и останавливается таймер; после возврата перечитываются auth/vault. Внешняя блокировка видна при ближайшем успешном poll; задержка ответа может увеличить интервал. При неподтверждённой собственной блокировке данные не возвращаются до явного повтора. Автоблокировку выполняет демон; оболочка не меняет её политику при скрытии/выходе.

Клиент не повторяет POST/PUT/PATCH/DELETE и не выводит серверные тела в логи/ошибки (они могут содержать секрет). Отображаются безопасный русский контекст и HTTP-код. Ошибки 401/429/501 различаются. Лимит соединений — 6, общий deadline RPC — 15 с. Проверка server SO_PEERCRED со стороны Dart не реализована; клиент использует защищённый P1 путь без symlink конечного сокета и без TCP fallback.

Подробности проверки и непроверенное: `docs/HANDOFF_desktop_shell_P2M1_2026-10-11.md` в корне репозитория.


## Контакты, чат и настройки M2

В «Контактах» введите имя и карточку `YANDI-NODE-1:...`: демон проверяет карточку и сохраняет доверие, затем отдельным запросом сохраняется контакт. При ошибке второго шага доверие уже могло сохраниться; существующий сервер также не сообщает ошибки записи contacts.json. Переименование и удаление перечитывают список; удаление требует подтверждения и не отзывает доверие или токен телефона.

«Открыть чат» выбирает конкретный контакт; история опрашивается только для выбранного разговора (GET телефону отмечает прочтение). Контакты/история — раз в 5 секунд; старше календарного года сообщения не показываются, максимум 100 из API. Полный ID из доверенной карточки позволяет запросить историю без разрешения короткого ID онлайн. Enter отправляет, Shift+Enter — новая строка. Повторная отправка во время запроса заблокирована; ошибка сохраняет черновик, POST не повторяется. Черновики раздельные для контактов в памяти текущего экрана и уничтожаются при навигации, скрытии и блокировке. Вложения показываются только как отметка, без скачивания/предпросмотра.

Настройки сохраняют имя профиля через PUT без периодического перезаписывания формы. Пароль входа меняется существующим восстановлением по мастер-паролю/коду; смена мастер-пароля API не предоставляет. Управление закрытой средой доступно здесь и на отдельной вкладке. Оболочка не получает её ключ и не расшифровывает историю сама.

## Группы M2, срез 2

«Группы» содержит свои группы, каталог и управление метаданными всех групп узла. Переписка доступна только участнику. Создание требует названия и тематики; тип — открытая группа или по приглашению. Вступление доступно из каталога или по строке `YANDI-GROUP-1:gid:code`. Для закрытой группы в каталоге отправляется просьба; модераторы могут ответить на неё, создать код или пригласить телефон по полному ID.

Участники видят роли и запрет писать. Матрица модерации совпадает с API: модератор управляет рядовыми, админ — также модераторами, владелец — всеми кроме владельца. Админов назначает только владелец. Исключение, блокировка, смена ролей и удаление записи требуют подтверждения; передача владения доступна только участнику с опубликованным ключом и задерживается на 3 секунды. Удаление группы всего узла отдельно требует пароль входа и уничтожает журнал и файлы.

Enter добавляет новую строку, Ctrl/Meta+Enter отправляет. Черновики разделены по группе и живут только в памяти экрана. Каждые 4 секунды перечитываются список, выбранная лента и участники; полный снимок удаляет уже показанные записи после удаления или запрета правилами. Видимая история ограничена календарным годом; серверное хранение оболочка не меняет. Формы настроек не перезаписываются опросом. Ключи вложений не сохраняются в модели; вложения только отмечаются, файлы и звонки групп не реализованы.

Лаборатория дополнительно проверяет жизненный цикл группы через `GroupRepository`: создание, ключ, текст, участники, приглашение, настройки, запрет ссылок, удаление сообщения и StepUp-удаление. Группа размещена на одном демоне; межузловой сценарий проверяет личный чат A↔B. Лимит JSON-ответа клиента — 1 МиБ: большая полная лента может быть отклонена до фильтра по времени. Подробности: `docs/HANDOFF_shell_m2_slice2.md`.

## Шлюзы, Relay и звонки M3

«Шлюзы» показывает сохранённые шлюзы и раздельные статусы HTTP/SOCKS5. CRUD проверяется перечитыванием списка, удаление требует подтверждения. Порт берётся из ответа демона; SOCKS-пароль живёт только на экране. Stop удаляет метаданные прокси; существующий API не подтверждает закрытие слушающего сокета. «Relay» показывает режим сервера, счётчики и сессии, позволяет включить/выключить сервер и отправить connect выбранному P2P peer.

«Звонки» использует общий координатор для голоса/видео узлов и телефонов. Входящие опрашиваются на открытом экране; навигация закрывает вызов. Ringing — 45 секунд, connecting — 30 секунд, disconnect grace — 10 секунд. Реальное медиа недоступно: в офлайн-кэше нет нативной Linux-библиотеки WebRTC. После accept подставной адаптер сообщает об этом и завершает вызов; сигнализацию можно проверять отдельно.

Демон должен включать исправление `src/web/ui_socket.rs`: прежний HTTP 101 содержал `Connection: close` вместо Upgrade. Лаборатория M3 проверяет gateway CRUD, HTTP/SOCKS metadata, Relay и voice/video accept/reject/end/SDP через настоящий Unix WebSocket двух временных узлов. Это проверка сигнализации, не аудио/видео.

Результаты и полный остаток паритета для P3: [HANDOFF_shell_m3.md](HANDOFF_shell_m3.md).
