# HANDOFF stream order v2 — 2026-10-11

Рабочая копия `/mnt/ssd480/wt/codex`, ветка `codex/stream-order`.
Уточнение к `5fc4264`, `16e23a3`, `3b886bc`: механизм offset/reorder/закрытия при дыре сохранён; совместимость и согласование формата отменены решением владельца. Исходного HANDOFF в этой рабочей копии нет, поэтому создан этот v2, заменяющий прежнее описание совместимости.

## Итоговый формат

### Блоки P2P-туннелей SOCKS5 и HTTP CONNECT (v1)

Между узлами данные туннеля передаются внутри YTP train или пакета BatchedWagon; прямой путь SOCKS5 (`PacketType::Socks5TunnelData = 0x52`) содержит тот же блок после внешнего байта типа. Это отдельный протокол от CONNECT телефона до компьютера (см. `docs/CLIENT_WIRE.md`). Оба типа используют один заголовок длиной 23 байта, но разные первые байты. Все многобайтовые числа — unsigned, big-endian.

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 1 | magic/type: `0xC8` SOCKS5, `0xC9` HTTP CONNECT |
| 1 | 1 | `version:u8 = 1` |
| 2 | 8 | `tunnel_id:u64` |
| 10 | 8 | `byte_offset:u64` — абсолютное смещение в этом направлении |
| 18 | 1 | `close:u8` — только 0 или 1 |
| 19 | 4 | `data_len:u32` |
| 23 | `data_len` | данные приложения |

Смещения начинаются с 0 независимо для каждого направления. Блок `close=1` всегда пустой и несёт итоговое смещение; закрытие ждёт всех предыдущих байтов. Общая длина должна быть ровно `23 + data_len`; обрезанный заголовок/payload, лишние байты, неверный close и переполнение `byte_offset + data_len` отвергаются. SOCKS5-парсер не принимает HTTP CONNECT и наоборот.

Получатель проверяет тип, затем версию до чтения длины, копирования payload и обращения к состоянию туннеля. Неизвестная версия (включая 0 и 2) отбрасывается с предупреждением в журнале и увеличением `tunnel_version_rejected` (`version_rejected` в `[STREAM-STATS]`); пакет не попадает в другие парсеры диспетчера и не закрывает существующие туннели. Невалидный v1 увеличивает `tunnel_stream_invalid`. Проверка происходит после обычной сборки train/распаковки batch, без дополнительных ресурсов туннеля для отвергнутого блока.

Offset обязателен: capability `STREAM_OFFSET`, выбор по peer table, JSON-блоки туннеля, SOCKS `[D7]`, прежний `[D8]` с FF marker и HTTP bincode/`YANDISO2` больше не поддерживаются. Запросы и ответы установки соединения сохраняют свои действующие форматы.

Буфер перестановки ограничен числом блоков и байтами; дубликаты и перекрытия не дублируют TCP-байты. `YANDI_RX_WORKERS>1` допускается без предупреждения UNSAFE. Потеря обеих полных копий блока оставляет дыру: по таймауту закрывается только этот поток, байты после дыры не выдаются. ACK/NACK отсутствуют, число полных копий остаётся не меньше двух.

## Изменения кода и тестов

- `src/netlayer/tunnel_wire.rs`: общий v1 codec, проверка без выделения payload, отдельный счётчик и журнал неизвестных версий, guard для диспетчера train/batch. `0xC8/0xC9` свободны среди существующих типов; `0xD8/0xD9` уже заняты карточками сети/цепочками.
- `ProxyTunnelData` и `Socks5TunnelData`: только `encode/parse`, обязательный `byte_offset:u64`, без serde-форм и skip-атрибутов. HTTP Request/Response bincode и SOCKS Request/Response JSON не менялись.
- Все четыре стороны туннелей: Cursor без выбора режима, writer всегда собирает поток по offset. Удалены capability, автоматическое объявление бита, peer-table методы и тест согласования.
- Диспетчеры train и batch отбрасывают некорректные типизированные блоки до попытки разбирать другие сообщения. Прямой SOCKS путь использует тот же v1 parser.
- Тесты v1/0/2, всех обрезанных префиксов и лишнего байта, flags, overflow, двух разных типов и всех прежних форм. Проверяются неизменность queue/reorder gauges при отклонении версии и возможность продолжить оба уже открытых туннеля. Сохранены реальные TCP-тесты обратного порядка и четырёх параллельных рабочих для обоих кодеков, а также gap/overflow/timeout/isolation.

## Границы и метрики

Reorder по-прежнему ограничен `YANDI_TUNNEL_REORDER_ITEMS` и `YANDI_TUNNEL_REORDER_BYTES` (не выше лимитов очереди туннеля). `YANDI_TUNNEL_GAP_TIMEOUT_MS` по умолчанию 5000 мс; при продвижении начинается срок следующей дыры, поздние блоки и дубликаты не продлевают текущую. Потеря обеих копий, overflow и ошибка записи закрывают только свой туннель. ACK/NACK и ретрансляций нет. Полный дубль ≥2 не менялся.

Метрики `[STREAM-STATS]`: `reordered`, `depth`, `bytes`, `gap_closed`, `overflow`, `duplicates`, `invalid`, новое `version_rejected`. Queue/reorder gauges освобождаются при штатном закрытии, ошибке и отмене writer.

Закрытая среда, маршруты выхода и остальные решения владельца не менялись. `~/node`, main и remote не использовались; push не выполнялся.
