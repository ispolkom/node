# Как участвовать

Спасибо, что хотите помочь. Правила короткие.

1. **Прочитайте [`docs/INVARIANTS.md`](docs/INVARIANTS.md).** Это обещания проекта (например, «выход не открывает домашнюю сеть»). Менять их можно только отдельным решением мейнтейнеров проекта, а не «заодно» с задачей. Тест `tests/invariants.rs` проверяет, что документ не расходится с тестами.
2. **Безопасность раньше новых функций.** К новой функции нужен тест на злоумышленника: подделка, повтор, мусорный ввод, перегрузка. Формат на проводе замораживается «золотыми» векторами (`docs/WIRE.md`): если байты изменились — повышайте версию протокола, а не правьте вектор.
3. **Зависимости — по минимуму.** Новая зависимость нужна с обоснованием; `cargo deny check` в CI должен проходить.
4. **Сборка и проверка перед запросом на слияние:**
   ```bash
   scripts/check.sh              # сборка + быстрые тесты
   scripts/check.sh полностью    # + сетевые тесты на настоящих процессах (нужен публичный адрес у машины)
   ```
5. **Секреты и адреса.** Не коммитьте ключи, пароли, журналы, адреса чужих машин. Список входных узлов меняется только через `yandi bootstrap …` и подпись владельца (см. [`bootstrap/README.md`](bootstrap/README.md)).
6. **Один запрос — одно изменение.** В описании: что и зачем, как проверено, что может сломаться.
7. **Уязвимости** — не в открытые задачи, а по [`SECURITY.md`](SECURITY.md).

Комментарии в коде и документы в основном на русском; английский тоже принимается.
