# Сквозное шифрование (E2E) — архитектурное предложение

Статус: **предложение, код не менялся.** Утверждения о том, что уже работает, подтверждены чтением кода и существующими тестами (ссылки ниже); всё остальное помечено «предположение» или «не проверено». Массовых изменений криптографии до утверждения этого документа и его независимой проверки не будет.

## 1. Цель
Промежуточные узлы передают и маршрутизируют, но не могут расшифровать пользовательское содержимое, для которого заявлено E2E; при этом сохраняются сообщения, файлы, звонки, доверенные узлы, многозвенные маршруты, восстановление соединения и отсутствие центрального сервера. Шифрование содержимого само по себе **не скрывает** сетевую метаинформацию (кто, когда, сколько, с какого адреса).

## 2. Карта доверия по видам данных
«Подтверждено» — реализация есть и покрыта тестами в репозитории; «не проверено» — нет тестов или проверок на устройствах.

**Итог:** настоящее E2E есть между телефонами, с компьютером-узлом как конечной точкой и в группах телефонов. **Нет** между узлами (веб-чат ПК и файлы узел ↔ узел), и звонки не проверены. Название «E2E» нельзя распространять на всё приложение — только на перечисленные сценарии.

## 3. Пробелы
1. **P-1 Узел ↔ узел только по звену** (инвариант I2): при ретрансляции чужой узел читает содержимое.
2. **P-2 Нет прямой секретности для получателя в E4:** ключ получателя долговременный; утечка его закрытого ключа раскрывает все записанные письма ему. Нет восстановления безопасности после компрометации (post-compromise security).
3. **P-3 Проверка личности собеседника:** закрепление ключа есть (подписанные связки), но удобной проверки отпечатков человеком («цифры безопасности») — не подтверждено; предположение: нужна.
4. **P-4 Группы:** авторство записей не подписывается индивидуально; доверие к ключу группы и первому знакомству (TOFU) — известные допущения.
5. **P-5 Несколько устройств одного человека и отзыв потерянного устройства:** своя политика ключей не описана единым документом.
6. **P-6 Звонки** не испытывались end-to-end в сети.
7. **P-7 Метаданные** (кто с кем, когда, сколько) не скрываются нигде, кроме режима цепочек для прокси.

## 4. Варианты
**Сообщения узел ↔ узел (закрывает P-1).**
- *A. Перенести проверенный конверт E4 на узлы.* Те же примитивы, общие векторы, подпись личности узла/человека, журнал повторов; ретранслятор видит только внешний слой «кому/откуда» и шифртекст. Плюсы: малый объём, готовые тесты и векторы, согласованность с телефонами. Минусы: тот же P-2 (без ratchet).
- *B. X3DH/PQXDH + Double Ratchet.* Прямая секретность и восстановление после компрометации; требует предключей и хранилища сессий, сложнее для асинхронной доставки через почтовый ящик и для нескольких устройств; крупный объём работы и риск ошибок реализации.
- *C. Noise (IK/XX) с периодической сменой ключей.* Проще ratchet; подходит для живых сеансов, хуже для офлайн-доставки.
Рекомендация: **A первым** (быстро убирает самый серьёзный пробел), затем исследовать **B** как улучшение P-2 для всех путей сразу. Выбор окончательно — после независимой проверки.

**Группы.** Сейчас — общий ключ с поколениями. Ближайшее дешёвое улучшение — подпись записи личным ключом автора (закрывает P-4). **MLS** оценить отдельно: хорош для больших групп, но тяжёл; решение — после опыта с A/B.

**Файлы.** Оставить схему «ключ на файл + проверка кусков»; для узел ↔ узел передавать ключ внутри конверта из варианта A. Возобновление передачи — с недостающих кусков, ключ не раскрывается ретранслятору.

**Звонки.** Оставить DTLS-SRTP; обязательная проверка: отпечаток DTLS сверяется с личностью собеседника через E2E-сигнализацию (не принимать звонок с несовпадающим отпечатком); смена ключей при смене маршрута; испытания с TURN и без него.

## 5. Ретрансляция и маршрутизация
Двухслойная схема: **внешний** заголовок маршрутизации (следующий переход, идентификаторы, размер) виден узлам, **внутренний** конверт — только конечным устройствам; ключ внутреннего конверта никогда не передаётся и не выводится из материала маршрутизации. Ретранслятор знает следующий переход, но не получает ключ получателя. Влияние: группы (ключи поколений не должны проходить через ретрансляторы открыто), вложения (ключ внутри конверта), звонки (сигнализация внутри конверта), восстановление маршрутов (повтор того же внутреннего сообщения под тем же номером, получатель отбрасывает дубль).

## 6. Обязательные свойства (по плану безопасности)
Проверка личности собеседника (закрепление ключа + отпечатки для человека); защита от подмены ключей (подписанные связки, версии); **защита от downgrade** (никакого отката на открытый текст — в телефонной части уже нет: `sendMessage` без ключа не отправляет; для узлов — версия формата и запрет отката); защита от повторов (журнал повторов — проверить, где он живёт при перезапуске); независимые ключи разных разговоров; безопасная смена ключей; несколько устройств; отзыв устройства; защита ранее переданного содержимого — в пределах модели угроз (P-2).
