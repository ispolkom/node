# HANDOFF: оболочка M2, срез 1 — 2026-10-12

Ветка `codex/shell-m2`, основа `4f49d4c`. Выполнен TASK_shell_m2_2026-10-12.md. Изменения ограничены desktop/yandi_desktop, chaos/desktop_shell_m1.py и этим документом; отдельная копия отчёта передана в каталог аудита по заданию.

## Реализовано

- Панель M1: состояние/идентификаторы узла, RX/TX и диагностические метрики, обнаруженные подключения. Убраны действия шлюза. Нереализованные daemon start/stop по-прежнему честно показывают 501, connected не меняется оптимистически.
- Контакты: список, поиск, состояния online/offline, добавление по карточке YANDI-NODE-1 (проверка ключа/ID — демон), переименование, удаление с настоящим подтверждением. Удаление записи не отзывает доверие или телефонный token; диалог это объясняет.
- Чат: выбор контакта, опрос выбранной истории каждые 5 секунд, отправка текста, Enter/Shift+Enter, один запрос отправки одновременно, раздельные черновики контактов в памяти текущего экрана. Полный peer ID берётся из доверенного списка, поэтому история не зависит от online-разрешения short ID. Свои сообщения определяются по полному node_id, текст отображается как Text/SelectableText. Timestamp API — миллисекунды; сортировка timestamp/msg_id, отметка edited и статус демона. Отбрасывается история старше календарного года; предел сервера — последние 100 сообщений.
- Настройки: чтение/PUT имени профиля, смена пароля входа по мастер-паролю/коду через существующий /api/auth/recover, закрытая среда setup/unlock/lock/recover/change_password/auto_lock. Смена мастер-пароля API отсутствует, это явно указано. Форма профиля не перезаписывается периодическим опросом.
- UnixApi поддерживает явные GET/POST/PUT/PATCH/DELETE. Динамические IDs ограничены допустимыми символами, пути с query, dot segments/encoded slash отклоняются; TCP fallback, proxy, cookies и автоматических повторов мутаций нет.
- При скрытии окна, выходе, потере связи и lock удаляются чувствительный subtree, контроллеры, сообщения, контактные снимки и черновики; открытые диалоги закрываются. Ответы проверяют revision разговора и epoch оболочки, в том числе между импортом карточки и сохранением контакта. Перед мутацией повторно проверяется vault/status. Ключ закрытой среды в оболочку не передаётся, собственной криптографии/хранилища нет.

## Границы и остаточные ограничения

Файлы отложены: multipart и последовательные чанки не являются простым путём; в истории есть только отметка вложения. Avatar upload, экспорт контактов, редактирование/удаление сообщений, устройства/сопряжение, группы, шлюзы/proxy, relay, звонки и расширенная сеть не входят в этот срез. Веб-UI сохранён, P3 не выполнялась.

Сохранение доверия карточке и запись контакта — два разных POST: второй может отказать после успеха первого. Старый daemon CRUD contacts.json глотает ошибки записи; перечитывание списка подтверждает наблюдаемое состояние, но shell не чинит этот серверный долг. История телефона использует существующий GET с mark-read, опрашивается только выбранный разговор; отдельный телефонный end-to-end прогон здесь не выполнялся.

Внешняя автоблокировка определяется ближайшим успешным опросом vault (номинально 1 секунда; задержка RPC может увеличить время). Неизменяемые Dart/Flutter String невозможно гарантированно физически стереть; это удаление ссылок/очистка контроллеров и ограничение времени жизни, не обещание полного зануления памяти. GTK-ручной проход всех новых форм с настоящим демоном не выполнялся; проверены widget tests, Linux сборка и API двух реальных узлов.
