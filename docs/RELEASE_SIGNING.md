# Подписанные выпуски ноды (Linux)

Цель: чтобы установленную или скачанную ноду нельзя было незаметно подменить. Принцип тот же, что у приложения: ключ подписи выводится из
фразы разработчика и нигде не хранится; открытый ключ публичен и закреплён у проверяющего.

## Что есть
- `src/release.rs` — манифест выпуска (версия, номер выпуска против отката, SHA-256 и размеры файлов) и подпись Ed25519 над точными
  байтами манифеста с доменным префиксом.
- `yandi-release` — инструмент: `pubkey`, `manifest`, `sign`, `verify`.
- `tools/node_release.sh` — сборка, детерминированный `tar.gz`, манифест, подпись, самопроверка.
- `release/yandi-release-pubkey.hex` — открытый ключ (создаётся при первой подписи, коммитится).
- `release/SEQ` — последний номер выпуска (коммитится, растёт на 1).

## Как выпускать
```
bash tools/node_release.sh          # спросит фразу (скрыто, дважды), создаст dist/yandi-node-<версия>-linux-<arch>/
bash tools/node_release.sh --check  # только проверить фразу по закреплённому ключу
```

## Как проверять скачанный выпуск
```
yandi-release verify <каталог выпуска> --pubkey <64 hex из release/yandi-release-pubkey.hex> [--min-seq <номер установленного>]
```
Выход `ВЫПУСК ВЕРЕН` означает: подпись манифеста верна ключом, подтверждённым у вас, версия не старше установленной, каждый файл совпадает
по размеру и SHA-256. Любое иное — не устанавливать.

## Что это защищает и что нет
- Защищает цепочку поставки: подмену архива на сервере или по дороге, подмену отдельных файлов, откат на старый выпуск.
- НЕ защищает от запуска чужой модифицированной ноды на чужом компьютере: без аппаратной аттестации другой узел этого проверить не может.
- Проверять должен установщик/обновлятор или человек командой `verify`; запущенная нода сама себя проверить не может.
- Сам `yandi-release` нужно брать из доверенного источника (прошлый проверенный выпуск или сборка из исходников), иначе подменят проверяющего.

## Ключи
Один ключ подписи, без иерархии. Если фраза утекла или потеряна: выпускается новый ключ, его открытую часть нужно заново закрепить у
проверяющих вручную. Корневой ключ с ротацией и отзывом — следующий этап. Windows (.exe) и .deb с подписанным индексом — следующие этапы.
