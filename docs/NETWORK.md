# Сеть: роли, режимы, как узлы находят друг друга

## Роли

- **Узел** — программа `yandi` на машине с **достижимым белым адресом**. Только такие машины становятся узлами сети: публикуют карточку, могут быть выходом и ретранслятором. Достижимость проверяется по факту (обратное подключение), а не по заявлению.
- **Клиент** — узел или устройство, до которого нельзя достучаться снаружи (за NAT оператора или роутера, телефон). Клиент не публикует карточку узла, держит исходящую связь с двумя ретрансляторами и объявляет подписанную запись «меня можно найти через них». О смене своего адреса клиент сообщает сам: он подключается к ретрансляторам заново и перевыпускает запись.
- **Ретранслятор** — обычный узел с проверенным адресом (флаг `relay` в карточке; выключается файлом `relay.json` `{"enabled": false}` или `YANDI_RELAY=off`). Клиент сам подключается к нему (исходящее соединение проходит NAT), и ретранслятор может продлить цепочку к клиенту по этому соединению. Он видит только зашифрованные слои.
- **Выход** — узел, через который трафик выходит в интернет со своего адреса. Кто может выходить, решает владелец узла (`/api/exit/settings`, страница «Настройки»): *никто* / *только доверенные* (по умолчанию) / *все*. На адрес самого компьютера и в домашнюю сеть выход не пускает никого и никогда.

## Как узлы находят друг друга

1. **Bootstrap.** Новый узел берёт подписанный список входных узлов ([`bootstrap/`](../bootstrap/README.md)), проверяет подпись закреплённым ключом и подключается к входам. Проверяется и ключ входного узла: по адресу из списка должен отвечать именно он.
2. **Карточки.** Каждый узел публикует **карточку**: страна (откуда известна), есть ли публичный адрес, мощность, задержка, адреса, чем помогает (выход, ретрансляция). Карточка подписана ключом узла и живёт 2 часа (перевыпуск раз в 30 минут и сразу при изменении — например при смене внешнего адреса).
3. **Обмен с соседями.** Узел раздаёт свою карточку и часть известных чужих каждому соседу, как списки пиров в торрентах. Подделки, просроченные, чужие ключи и непроверенные карточки отбрасываются.
4. **Проверка достижимости.** Каждая принятая карточка проверяется обратным подключением: узел стучится по TCP на заявленный адрес (на порт основной связи) и требует подпись ключом из карточки под свежей случайной строкой. Не отозвался — карточка остаётся «непроверенной»: её нет в списках по странам, она не выбирается в выходы и цепочки и не раздаётся дальше. Чужая карточка не может заставить узлы стучаться в домашние сети: проба идёт только на публичные адреса.
5. **Клиенты.** Запись доступности (`ViaRecord`) раздаётся тем же обменом. Тот, кто знает номер и ключ клиента (свои устройства, доверенные), находит его ретрансляторы по записи.

## Режимы работы с интернетом

| Режим | Как запустить | Что происходит |
|---|---|---|
| **Быстро** | `socks5 auto [NL]`, `POST /api/socks5/start/auto[-NL]`, страница настроек | прямой путь через один выход; выход виден по адресу, содержимое HTTPS ему не видно |
| **Быстро, только нужные сайты** | `…/start/rules[-NL]` | сайты из правил (встроенный список или `route_rules.json`) идут через выход, остальные — напрямую с вашего компьютера (только адреса в интернете) |
| **Анонимно** | `socks5 hops [NL]`, `…/start/hops[-NL]` | цепочка вход → средний → выход, шифрование слоями; ни один узел не знает вас и цель одновременно. Выход открывает **только веб-порты 80 и 443** |
| **Личный шлюз** | `POST /api/socks5/personal` | своё устройство ходит в интернет через свой компьютер (дома или за NAT, при необходимости через ретранслятор) по секрету владельца (`GET /api/devices/pairing`); любые порты, домашняя сеть закрыта |

Выход выбирается автоматически: фильтр по стране и связи, порядок по качеству (известная страна, мощность, задержка), чередование по соединениям, отдых сбойного выхода (60 секунд, дальше вдвое дольше), **проверка страны по факту** (узел спрашивает выход через него самого, из какой он страны; обманувший исключается).

## Вход для телефона по TLS

Если владелец включил (`YANDI_MOBILE_TLS_PORT=443` или `mobile_tls.json` `{"port": 443}`), узел принимает TLS (самоподписанный сертификат, отпечаток показывает `GET /api/devices/pairing`) и передаёт байты своему локальному SOCKS5-прокси. Тот, кто не начал с приветствия SOCKS5, получает обычную страницу сайта (своя `decoy/index.html` в папке данных или встроенная) и 404 на всё лишнее. Для провайдера это HTTPS внутри одной страны.

## Взаимность

Узел, который по карточке мог бы выпускать других в интернет (публичный адрес, достаточная мощность), но выход выключил, после льготного объёма (100 МБ) теряет бесплатную помощь выхода «для всех»; владельцу на странице настроек показывается честное предупреждение. Доверенные узлы, телефоны и слабые машины правилу не подчиняются.

## Настройки окружения

| Переменная | Назначение |
|---|---|
| `YANDI_BOOTSTRAP_URL` | другой адрес списка входных узлов (через запятую — несколько) |
| `YANDI_CLIENT_ONLY=1` | считать этот узел клиентом (не публиковать карточку, жить через ретрансляторы) |
| `YANDI_RELAY=off` | не быть ретранслятором |
| `YANDI_MOBILE_TLS_PORT` | порт входа для телефона по TLS |
| `YANDI_EXIT_PORTS=any` | разрешить выходу по цепочке любые порты (только для проверок) |
| `YANDI_GEO_PROBE=адрес:порт` | служба страны для проверки выходов (только для проверок) |
| `YANDI_TESTNET=1` | тренировочный режим: пробы и проверки допускают адреса этой машины |

## Известные ограничения

- Цепочки: нет подмешивания пустого трафика и закрепления входного узла; нет управления потоком (быстрый источник упирается в очередь отправки); ячейки одной цепочки могут приходить не по порядку — поток собирается по номерам.
- Клиент не возвращается в «узлы» сам; у ретранслятора нет лимитов на клиента, кроме общего числа цепочек.
- Запись доступности клиента видна всем (номер клиента и номера его ретрансляторов): это публичное объявление «я на связи».
- Страна выхода «известна» из карточки или по внешнему адресу; её проверяет только измерение через сам выход.
