# Формат на проводе (закреплённая часть)

Здесь описано то, что уже закреплено «золотыми» тестами и не должно меняться молча. Любое изменение формата — это повышение версии и осознанное решение. Остальные типы пакетов (DHT, ретрансляция, туннели, прокси, звонки) ещё не заморожены и описываются по мере закрепления.

## 1. Пакет сеанса (шифрованный)

Версия формата: **2**. Пакет:

```
[номер отправителя: 32] [одноразовый номер: 12] [шифртекст ‖ тег GCM: n+16]
```

* Одноразовый номер: `[версия: 1 = 0x02] [соль сеанса: 5] [счётчик: 6, big-endian]`. Счётчик начинается с 1 и растёт на 1 с каждым пакетом отправителя. Соль — 40 случайных бит, выбираются при создании сеанса.
* Шифр: AES-256-GCM. Ключ — направленный, из общего ключа сеанса: `HKDF-SHA256(salt = нет, ikm = общий ключ, info = "yandi-v2 key low->high")` для направления «меньший номер узла → больший» и `"yandi-v2 key high->low"` для обратного.
* AAD: байт версии (`0x02`) ‖ номер отправителя (32 байта).
* Внутри шифртекста: `[длина данных: 4, little-endian] [данные] [заполнитель из нулей]`; заполнитель 8–32 байта для данных короче 64 байт, иначе 0–8.
* Получатель принимает пакет, только если версия `0x02`, подлинность проверена, а счётчик не встречался и не старше окна в 2048 пакетов (скользящее окно, обновляется только после успешной проверки).
* Потолок: 2^32 пакетов под одним ключом (дальше отказ); после часа или 2^28 пакетов узлы договариваются о новом ключе (`YANDI_REKEY_AFTER_SECS` меняет час). Прежний ключ ещё 30 секунд принимает пакеты в пути (не больше двух прежних ключей).
* «Золотой» вектор: общий ключ `07…07` (32 байта), номера узлов `01…01` и `02…02`, соль `aa bb cc dd ee`, счётчик 1, данные `golden`, AAD `02 ‖ 01…01` → шифртекст с тегом `4bd3c4d90dd64958679aa40615886a59cc95f45f606e`. Получен независимо (Node.js/OpenSSL). Тест: `src/crypto/session.rs::golden_vector`.

## 2. Рукопожатие с одноразовыми ключами

1. Инициатор делает одноразовую пару X25519 и отправляет публичную половину в приветствии-приглашении (поле `x25519_public`); номер приглашения — `nonce` приветствия. Секрет хранится до подтверждения (не больше 64 неотвеченных приглашений) и стирается при использовании.
2. Ответчик делает свою одноразовую пару, считает `shared = X25519(e_r, E_i)`, сохраняет сеанс (секрет не хранит) и отправляет публичную половину в подтверждении (`x25519_public`, `nonce` = номер приглашения).
3. Инициатор считает `shared = X25519(e_i, E_r)` и сохраняет сеанс.
4. Общий ключ сеанса: `HKDF-SHA256(salt = нет, ikm = shared, info = "YANDI session key")`, 32 байта. Нулевой общий секрет (слабая точка) — отказ.
5. Встречное знакомство (оба пригласили друг друга одновременно) оканчивается одним ключом: остаётся рукопожатие, начатое узлом с меньшим номером; проигравший ключ 30 секунд принимается только для расшифровки.

## 3. Приветствие основной сети (UDP, порт обнаружения)

```
"NET1" [тип: 1 (0=запрос, 1=подтверждение)] [версия: 1] [номер узла: 32] [имя узла: 32 = SHA-256(публичный ключ)]
[публичный ключ Ed25519: 32] [x25519_public: 32] [подпись: 64] [cid: 8] [возможности: 2 BE] [время: 8 BE] [nonce: 8 BE]
[wan: длина 1 + байты] [lan: длина 1 + байты] [точка обнаружения: длина 1 + байты]
[ipv6_virtual: флаг 1 (+16 байт)] [ipv6_external: длина 1 + байты] [p2p_data_addr: длина 1 + байты]
[p2p_x25519_public: флаг 1 (+32 байта)] [юрисдикция: длина 1 (≤ 8) + байты]
```

* Строки: 1–255 байт; пустая строка запрещена (на проводе она неотличима от «нет значения»); длинная не усекается (отказ при записи).
* **Подпись** — Ed25519 по следующим байтам (**все поля, кроме подписи**): `"yandi-hello-v2" ‖ 0x00 ‖ тип ‖ версия ‖ номер узла ‖ имя узла ‖ публичный ключ ‖ x25519_public ‖ cid ‖ возможности ‖ время ‖ nonce ‖` затем по порядку wan, lan, точка обнаружения, ipv6_virtual, ipv6_external, p2p_data_addr, p2p_x25519_public, юрисдикция; необязательное значение — `0x00` (нет) или `0x01 ‖ [длина 4 BE для строки] ‖ байты`. Тест: `src/netlayer/packet.rs::the_signed_bytes_are_frozen` (SHA-256 подписываемых байт получен независимой сборкой в Python), `changing_any_single_field_breaks_the_signature` (25 изменений полей).
* Принимающий сначала проверяет подпись и соответствие имени ключу, затем окно времени (±5 минут) и допуск (см. раздел 5), затем повтор `(номер узла, nonce)`.

## 4. Приветствие канала переписки (UDP)

Сериализация — `bincode` структуры `P2PHelloPacket`; подпись Ed25519 по `canonical_bytes()` (версия, номер узла, `x25519_public`, время, nonce, длина и байты `p2p_data_addr`, публичный ключ Ed25519). Правила приёма те же: подпись, повтор, допуск.

## 5. Допуск новых узлов (правила приёма приветствий)

* Известный узел (уже в таблице): не чаще 20 приветствий в минуту.
* Новый узел: не больше 10 с одного адреса в минуту, не больше 300 на весь узел в минуту; таблица пиров не превышает `20 × max_connections(мощность)` (200 / 1000 / 3000).
* При полной таблице вытесняется самый давний неприкреплённый узел, не якорь, молчащий не меньше двух минут; если такого нет — отказ.
* Тесты: `src/netlayer/admission.rs`, `tests/hello_flood_test.rs`, `tests/p2p_hello_flood_test.rs`.
