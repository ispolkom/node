## 3. Что проверено на физических устройствах
Источник: `docs/DEVICE_TEST_RESULTS.md` (стенд: телефон Infinix X6517, Android 12, один узел на ПК владельца с белым адресом, пакет `0.2.0+g712`).
- Wi-Fi без прокси: связь с узлом есть.
- Переключение Wi-Fi → мобильная сеть и обратно: возврат на Wi-Fi — соединение через 3 с; время переподключения по LTE точно не измерено.
- Падение узла (`kill -9`, перезапуск systemd): телефон восстановил связь через 27 с.
- Через стороннее приложение Super Proxy (VPN): соединения на узел приходят с адреса прокси, держатся стабильно минуту.
- Пакет `0.2.0+g716`, колокольчик со счётчиком и пропущенные звонки: показ числа у колокольчика при запертой закрытой среде подтвердил владелец на своём ПК (в том числе «при нажатии Войти без пароля»).

## 4. Что НЕ проверялось (список честно)
- Сообщения и файл во время переключения сети; повторы очереди при обрыве.
- Rekey при активном трафике на телефоне; два телефона; голосовые и видеозвонки в реальных сетях; цепочки через 3–4 узла на физических сетях; проход до адреса в интернете на настоящем выходе (`hops`, `exit`, `personal`, `rules`).
- Кнопка VPN внутри приложения YANDI (по `adb input tap` служба не запускается, причина не установлена).
- Мёртвые соединения на узле после ухода Wi-Fi держатся минуты (проверка keepalive не сделана).
- Пакеты Windows, macOS, iOS не собирались.
- Работа на Ubuntu (пакеты собраны на Debian 12, требуют glibc 2.36 и новее).
- Не-Unix платформы для библиотеки восстановления и замков файлов (компиляция и запуск не выполнялись).
- Ошибки `fsync` каталогов, потеря питания, `kill` во время записи, процессы, не берущие замок файлов связи.

## 6. Угрозы: закрытые и открытые
Источник: `docs/SECURITY_STATUS.md` (136 записей кругов 30–40 и последующих). **Статус «Закрыто» не присвоен ни одной записи:** независимые проверки Sol принимают исправления частично, а физических испытаний по ним нет.
- Исправлено в коде и проверено автотестами, ждёт повторной независимой проверки: около 105 записей, включая все пункты восстановления из копии и файлов связи (круги 36–41).
- **Открыто (30 записей):** блокеры этапа 2б (`H18-2…7`, `P20-7…10`) и E1 (`E18-3`, `E18-4`, `P20-11`, `P20-12`), `P11-3` (обновление прежних замков с четырьмя словами), прежние архитектурные замечания E17 и пункты проекта 2б из круга 35 (`P15-3…7`, `P15-12`). Это проекты и решения, не реализованный код.
- **Ограничения приватности**, которые нужно говорить прямо: узел читает переписку «телефон ↔ ПК владельца» (он конечная точка) и пересылаемые через него сообщения телефона внешнему компьютеру; метаданные (кто, когда, сколько байт) узлу видны; выходной узел цепочки видит данные к интернет-цели; якорь WS — конечная точка своего канала; нет прямой секретности для хранимого содержимого и нет асинхронного E2E-слоя между компьютерами (E1 не внедрён, блокеры в `docs/E2E_ARCHITECTURE.md`, раздел 12).

## 7. Ограничения версии
- Версия **тестовая**: служит для проверки и поиска ошибок; не для важных данных и критичной связи.
- Закрытая среда узла запечатана ключом устройства машины: компрометация работающей машины раскрывает её (риск принят, `docs/PRIVACY.md`).
- Один узел на ≈100 доверенных клиентов — ориентир, нагрузочных испытаний нет.
- Реестр и документы описывают состояние кода; проекты 2б и E1 **не реализованы**.

## 8. Что нужно для следующего шага к «стабильной»
1. Исполняемый сценарий испытаний на физических устройствах (`tools/device_test.sh`), прогнанный на нескольких сетях и двух телефонах, с таблицей результатов.
2. Решение по окружению для тестов `hops/exit/personal/rules` (машина без петли), чтобы отделить регрессии от среды.
3. Закрытие блокеров 2б (чистый автомат с поддельными часами, векторы) и только после этого — интеграция в рабочую сеть.
4. Повторная независимая проверка исправлений восстановления.
