# Роадмап R9 (2026-10-21): гости везде, ПК виден, автономные узлы, сигналы целостности
*Roadmap R9: guests on every device, the PC is visible, autonomous nodes, integrity signals.*

Решения владельца из обсуждения 2026-10-21. Порядок работ: код → журнал → Codex проверяет → тесты (Sonnet) → одна сборка.

## 0. Термины / Terms
* **Узел** — ПК/сервер с `yandi-node`. **Клиент** — телефон, планшет, оболочка ПК. Телефоны и планшеты узлами НЕ являются.
* **Роли устройств на узле:** владелец (QR), пользователь (принят владельцем), гость (без QR, урезан).
* **Режим узла** (выбор есть только у узла с белым IP и достаточным железом; остальные всегда в общей сети):
  **общая сеть** или **автономный**. Или-или.

## 1. ПК виден участникам и гостям (баг живого теста)
Было: ПК («Компьютер») видели только телефоны владельца. Узел не давал гостю строку узла, приложение выбрасывало её из
каталога, письма пользователя/гостя на ПК отбрасывались.
Стало: пользователь и гость видят ПК в «Пользователях» и пишут ему (E2E, как телефон владельца). Читать чужую переписку
владельца по-прежнему нельзя: `/mobile/chat/*` и `/mobile/contacts` закрыты не-владельцу. Повышенный до пользователя —
полный участник.

## 2. Гости на всех устройствах
* Гостем может быть телефон, планшет и ПК (оболочка в режиме гостя, без своего узла) — одна оболочка, урезанные возможности.
* Можно: люди онлайн (включая ПК и другие компьютеры), переписка с любым участником, **не больше 10 сообщений в сутки**
  (на все чаты вместе), аудиозвонки 15 мин / 60 мин в сутки, жалобы, ник и картинка, запрос статуса.
* Нельзя: группы, прокси/VPN, видео, приглашения, чтение переписки владельца.
* **Аккаунт гостя живёт 24 часа от создания** (абсолютно), затем стирается; новый вход — новый гость.
* **Жалобы:** любой пользователь или гость жалуется на спам; 3 жалобы от разных устройств за сутки — гость удаляется.
* **Потолок гостевых файлов на узел** (сумма по всем гостям, по умолчанию 2 ГБ): сверх — отказ «узел занят»;
  сообщения при этом идут.
* В общей сети гость видит в каталоге «Узлы» только узлы из подписанного списка с ролью `guest`.

## 3. Карточка «Узлы» на странице поиска (телефон и оболочка)
Число известных узлов и список с прокруткой: короткий номер, «в сети», регион (если узел его объявил), роль.
Офлайн не выводится (даже из bootstrap). Никаких адресов, ключей, IP. Владелец/пользователь видят все известные онлайн-узлы,
гость — только гостевые из подписанного списка. У автономного узла карточка показывает только узлы его меша.

## 4. Автономный узел
* Настройки узла: стилизованный чекбокс «Автономный узел» + кнопка «Применить», окно с последствиями (ru/en).
* Работает всё для своих: клиенты, гости, звонки (свой TURN), файлы, группы, свои прокси.
* С общей сетью — ничего: нет bootstrap, DHT, обмена соседями, хопов/транзита/выходов, заявок в список, mDNS,
  проверки и рассылки обновлений (обновляет владелец вручную). Входящие от неизвестных узлов молча отбрасываются.
* **Меш:** автономный узел сопрягается ТОЛЬКО с автономными, явно и взаимно (ключ вносится вручную с обеих сторон).
  Публичный узел с автономным не соединяется никогда, и наоборот.
* **Смена режима** стирает сетевые данные другого мира: кэш bootstrap, DHT, соседей, список меша. Ключ узла один,
  режим — статус; в рукопожатие подмешивается метка мира (`yandi-global-v1` / `yandi-mesh-v1`), поэтому узлы разных миров
  не примут друг друга даже по ошибке.

## 5. Сигналы целостности (без скрытых механизмов)
Скрытые недокументированные проверки «свой-чужой» не делаем: в открытом коде они находятся и вырезаются, а сеть с тайным
поведением выглядит как закладка. Вместо этого:
1. **Поведение, а не слова** — взаимность (`reciprocity.rs`), жалобы и лимиты гостей.
2. **Версия и сборка в карточке узла** — мягкий сигнал (подделать можно; полезно для диагностики и приоритета).
3. **Пиннинг ключей в меше** — внутрь только по внесённому ключу.
4. **Минимальные версии в подписанном списке** (`min_node`, `min_app`): честные узлы и приложения сами отказываются от
   отозванных сборок, узел отвечает старому приложению «обновите приложение».

## Честные границы / Honest limits
* Модифицированный узел может соврать о версии и метке мира; проверить код удалённой машины нельзя (нет аттестации).
* Свой человек, внесённый в меш, может запустить изменённый узел в обоих мирах — защита только организационная.
* Лимиты гостя считаются на ключ: новый ключ обнуляет их; поэтому есть потолок числа гостей (64) и потолок файлов на узел.
* Узел при прямом соединении технически видит IP гостя (см. `GUEST.md`).
