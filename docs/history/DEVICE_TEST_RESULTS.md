## Стенд
- **Телефон:** Infinix X6517, Android 12; приложение YANDI 1.0.0 (`1.0.0-b1`), APK из коммита `53fd62d`-ветки (SHA-1 `36bff5ea…`; код приложения с тех пор не менялся); отдельное стороннее приложение Super Proxy (`com.scheler.superproxy`) с профилем HTTP-прокси «нл» (Нидерланды, внешний адрес `45.147.182.91`).
- **Узел:** ПК владельца, systemd `yandi-node`, пакет `0.2.0+g712` (коммит `9bcbcd6`), белый адрес `185.77.205.3`, вход телефона по TLS на порту 8444.
- **Сеть дома (со слов владельца и по `ip addr`):** телефон → Wi-Fi-роутер → внутренняя карта ПК (`192.168.100.1`) → внешняя карта ПК → интернет → обратно на узел по внешнему адресу. То есть по Wi-Fi телефон идёт к узлу «петлёй» и виден узлу как `192.168.100.10`. Мобильная сеть: МегаФон LTE (по словам владельца, интернет там нестабилен из-за глушения).
- **Измерения:** со стороны узла — `ss` по портам 8443/8444 (адрес источника каждого соединения, раз в секунду); со стороны телефона — `adb shell` (`ip`, `dumpsys connectivity`, `nc`), дерево доступности (`uiautomator`). Экран приложения защищён от снимков.

- Подтверждение получения сообщения T6 на ПК: закрытая среда узла заперта после перезапуска (T4), а подобранный пароль не подошёл (1 неверная попытка из 5 на закрытой среде; ранее одна неверная попытка входа в админ-панель). Нужна проверка владельцем в оболочке ПК.

- Кнопка **VPN** внутри приложения YANDI: `input tap` не запускает службу (в `logcat` ничего, `dumpsys` — службы VPN нет); разрешение VPN у приложения выдано. Причина не установлена (ошибка кнопки или способ нажатия) — **открыто**.
- Rekey при активном трафике на телефоне; два телефона; звонки; маршрутизация через 3–4 узла на физических сетях.
- Время переподключения по LTE не измерено точно.

## Наблюдения
1. После отключения Wi-Fi на узле ещё долго остаются соединения с прежнего адреса телефона (2 шт., минуты): мёртвые TCP-соединения не закрываются быстро. Стоит проверить keepalive и таймауты на стороне узла (не обязательно ошибка, но нагрузка при многих клиентах).
2. Приложение запирается при уходе в фон и просит пароль заново (так задумано).
3. Особенность стенда: узел не может подключиться к собственному публичному адресу изнутри (петля), поэтому тесты `testnet_hops/rules/exit/personal` («дойти до адреса в интернете») на этом ПК не проходят и на старом коммите.
