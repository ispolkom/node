## Реализовано

- В навигации «Группы»: свои группы, каталог, управление узла; создание invite/open с проверкой названия 1–64, обязательной темы 1–40 и описания до 300 символов. Вступление по ID/строке YANDI-GROUP-1; open join и invite request из каталога. Удалённые/исключённые группы отмечены отдельно, forget требует подтверждения.
- Выбранная группа: текстовая лента, собственные сообщения по daemon `mine`, plain Text/SelectableText, timestamp в миллисекундах, сортировка ts/seq, отбрасывание истории старше календарного года с календарной поправкой 29 февраля. Полный GET без after каждые 4 секунды заменяет снимок, поэтому deleted/system/deny не оставляют старые записи в UI. Список и info также опрашиваются в этом цикле без наложения запросов.
- Отправка: Enter — новая строка, Ctrl/Meta+Enter — send, trim nonempty и предел UTF-8 8000 байт. Один запрос мутации одновременно, POST не повторяется; ошибка сохраняет черновик. Черновики разделены по gid только в памяти текущего экрана.
- Участники, роли и запрет писать; приглашение кодом и телефону по полному ID; ответы на просьбы (accept/skip/never). Mute/unmute/kick/ban/unban/promote/demote/make_admin по матрице API. Moderator — member, admin — member/moderator, owner — остальные кроме owner; make_admin только owner. Передача владения только owner, target с has_key, реальное подтверждение с задержкой 3 секунды. Удаление сообщения доступно staff по роли автора, включая собственные/ушедших авторов как в API.
- Owner/admin изменяют название/тему/описание и правила видов 2–6. Редактирование в отдельной форме, опрос не перезаписывает несохранённый текст. Деструктивные действия/смена роли требуют настоящего диалога подтверждения. Отдельное управление узла показывает метаданные, не вызывает feed для групп, в которых ПК не участвует. Полное удаление через /api/mobile/groups/{gid}/delete требует StepUp password и предупреждает об уничтожении журнала и файлов; поле пароля очищается при закрытии формы, пробелы в пароле сохраняются.
- Banners damaged/problem/no-key/muted/deny; без ключа или при проблеме composer закрыт. После ошибки обновления feed/info удаляются, старая лента не выглядит актуальной.
- До мутации повторно проверяется vault; epoch оболочки и revision группы защищают поздние ответы. Общий механизм M1 закрывает диалоги и уничтожает subtree при lock/hide/disconnect/logout/navigation. Удаляются контроллеры, ссылки на снимки, приглашения и черновики. Репозиторий сохраняет лишь поля для отображения сообщений, целый body/ключи вложений в модели не удерживает. В текущем Rust ui_body уже удаляет k; Dart дополнительно не переносит attachment body в модель. Собственного decrypt/хранилища/логирования тел нет.
- Файлы групп и звонки не реализованы; в ленте только отметка вложения. Веб-UI сохранён, P3 не выполнялась. Rust, системные службы и боевой узел не изменены.

## Ограничения и непроверенное

- Межузловой настоящий сценарий проверяет личный чат A↔B. Группы размещаются на конкретном демоне и предполагают участие его телефонов/ПК; два daemon-PC не составляют группу через этот API. Поэтому настоящий group lifecycle проверен на узле A, а добавление/исключение телефонов, запросы, роли и передача — в widget tests с подставным API. Отдельного телефонного E2E и ручного GTK прохода не было.
- UI ограничивает видимую историю календарным годом, срок серверного хранения не меняет. Полная лента загружается до фильтрации; существующий предел UnixApi 1 МиБ может отвергнуть большую ленту. При ошибке выводится безопасное сообщение, старый feed удаляется; pagination API не предоставляет, лимит не повышен.
- Телефон для приглашения задаётся полным ID; демон проверяет допустимость. Отдельный picker /api/groups/devices (ARRAY) не реализован, транспорт по-прежнему принимает только object JSON.
- Ошибки API остаются безопасными типом/HTTP-кодом, без разбора русских серверных строк. Модель permissions помогает UI, окончательная авторизация всегда у демона.
- Внешний vault lock обнаруживается общим успешным poll (обычно 1 секунда, задержки RPC могут увеличить интервал). Уничтожение ссылок/очистка контроллеров не гарантирует физическое зануление неизменяемых Dart/Flutter Strings. Secret ответа/входных полей на диск не пишется.
