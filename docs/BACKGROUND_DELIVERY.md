# Фоновая доставка YANDI без Google

YANDI не использует FCM или другой обязательный сервис Google. На Android доставка выполняется собственным foreground-сервисом, который держит одно TLS/WebSocket-соединение с выбранной нодой. Нода передаёт зашифрованные кадры сообщений и сигналов звонка; native-слой не расшифровывает содержимое.

Сервис использует адаптивный режим энергопотребления:

- экран включён: служебный ping каждые 30 секунд;
- экран выключен: ping каждые 180 секунд;
- Doze: ping каждые 300 секунд, плюс системный TCP keepalive;
- при потере сети соединение закрывается и восстанавливается после `NetworkCallback`;
- при перезагрузке Android сохранённая конфигурация восстанавливает сервис без Flutter;
- неподтверждённые сигналы звонка хранятся локально в ограниченной очереди и передаются Flutter после открытия приложения.

Это даёт независимую push-доставку при разумном расходе батареи. Полностью «без процесса и без батареи» на Android гарантированно работать нельзя: ОС не предоставляет сторонним приложениям независимый wake-up канал. Поэтому YANDI сохраняет режим надёжной доставки для звонков и сообщений, а не имитирует push через частые таймеры.

Следующий отдельный этап — собственный push-relay. Он может доставлять короткий зашифрованный wake-envelope через независимую инфраструктуру (например, self-hosted UnifiedPush-дистрибьютор), после чего приложение открывает обычное TLS-соединение к ноде и забирает данные. Relay не должен получать текст сообщений, ключи или телефоны. До появления такой инфраструктуры текущий WebSocket foreground-сервис остаётся основным транспортом: он уже работает без Google и не требует внешнего поставщика push.
