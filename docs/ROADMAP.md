# План развития

Это живой план проекта: что уже есть, что дальше и в каком порядке. Порядок выбран так, чтобы замысел не «уплывал» при развитии.

## Принципы

1. **Замысел закреплён документом и тестами.** `docs/INVARIANTS.md` — короткий список обещаний проекта; каждое охраняется тестом, а `tests/invariants.rs` следит, чтобы документ не разошёлся с тестами. Изменить обещание можно только осознанным отдельным решением.
2. **Формат на проводе замораживается.** Для закреплённых пакетов есть «золотые» векторы (`docs/WIRE.md`): если байты изменились, тест падает, пока не повышена версия протокола.
3. **Безопасность раньше новых функций.** К новой функции нужен тест на злоумышленника: подделка, повтор, мусорный ввод, перегрузка.
4. **У каждой фазы — критерий «готово», проверяемый командой**, а не словами.
5. **Живучесть важнее скорости.** Стабильное поведение в час пик лучше рекордов; запасные пути не убирать.
6. **Честность про анонимность.** Сеть не называется анонимной, пока не закрыты пункты инварианта I21.

Размеры: S — до пары дней работы, M — неделя-две, L — месяц и больше.

## Модель сети

- **Узлы** — машины с достижимым (белым) адресом. Сеть узлов открытая: узлы находят друг друга сами по подписанному списку входных узлов (`bootstrap/`).
- **Клиенты** (устройства за NAT, телефоны, компьютеры без белого адреса) работают через ретрансляторы. Новых людей подключают **по приглашению** узла.
- Ключи переписки живут на устройствах людей; узел — почтовый ящик и ретранслятор: он видит шифртекст и метаданные (кто с кем и когда), но не содержимое.
- Клиент не привязан к одному узлу: его личность (ключи) независима от узла.
- Случайный узел клиенту не назначается: это защищает его от злонамеренных узлов.

## Что уже есть

- Шифрование звена (X25519 + HKDF + AES-256-GCM, одноразовые ключи на каждое рукопожатие, счётчики и окно повторов, смена ключей без потери пакетов), формат закреплён «золотыми» векторами.
- Подписанные приветствия, ограничение наплыва поддельных личностей, устойчивость разборщиков к враждебным байтам (в том числе фаззинг каждого разборщика в отдельном процессе).
- Переписка с подтверждением прочтения, файлы, сигналы звонков; страница управления на `127.0.0.1` с защитой входа.
- Выход в интернет через другие узлы: автоматический выбор по стране и качеству, измерение страны выхода, режимы «быстро» и «анонимно» (цепочка из трёх узлов с шифрованием слоями), правила по сайтам, личный шлюз для своих устройств, взаимность.
- Подписанные карточки узлов, проверка достижимости обратным подключением, клиенты за NAT через ретрансляторы, подписанные записи доступности.
- Вход для телефона по TLS с сайтом-маскировкой.
- Подписанный bootstrap и инструменты владельца списка.
- CI: сборка на Linux, Windows и macOS; сетевые тесты на настоящих процессах; проверка зависимостей.

## Дальше

### Фаза 1. Закрыть оставшиеся дыры (L)
- **Отправитель подписывается** (подмена отправителя на основной сети), заголовки пакетов минимизируют метаданные (номер отправителя шифруется).
- Убрать `unwrap`/`expect` с пути обработки чужих данных там, где они остались; расширить фаззинг.
- Шифровать контрольные точки передач на диске; проверять владельца при чтении секретов.
- Хранить секрет возобновления сеанса, а не ключ сеанса.
- Мутационная проверка критичных модулей: тесты должны ловить намеренные поломки.
- **Готово, когда:** в карте шифрования (`docs/CRYPTO_MAP.md`) нет открытых критичных и высоких дефектов, фаззинг покрывает каждый разборщик.

### Фаза 2. Надёжный транспорт (L)
- Запасной путь по TCP (выглядит как обычный HTTPS) и автоматическое переключение при потерях или потере приоритета UDP.
- Регулятор скорости и управление перегрузкой, ограниченные очереди (чтобы память не росла при задержках без потерь).
- Избыточность по необходимости (копии для коротких, чувствительных к задержке пакетов; восстановление потерь вместо полного дублирования для больших потоков) — отдельный профиль для звена «телефон — компьютер».
- Замеры скорости как часть тестов: воспроизводимый стенд.
- **Готово, когда:** на канале с потерями и на канале с задержкой скорость не падает ниже заданного порога (тест-стенд).

### Фаза 3. Общение по-настоящему (L)
- Сквозное шифрование между устройствами людей (сейчас шифруется каждое звено).
- Проверка ключей собеседника (короткий код), прямая секретность для каждого сообщения.
- Видеозвонки: очередь входящих, API, интерфейс.
- **Готово, когда:** посредник и ретранслятор не могут прочитать переписку (тест), смена ключа собеседника замечается.

### Фаза 4. Цепочки и выход (M–L)
- Подмешивание пустого трафика и закрепление входного узла — условие, чтобы сеть можно было называть анонимной против наблюдателя всей сети (I21).
- Управление потоком в цепочках; лимиты ретранслятора на клиента; жалобы и блокировка клиентов; возврат клиента в узлы сети.
- Мосты: адреса узлов, которые раздаются только доверенным (защита от перечисления узлов).
- **Готово, когда:** выполнены условия I21.

### Фаза 5. Клиент как отдельная программа и приглашения (L)
- Протокол «клиент — узел» — отдельная маленькая замороженная спецификация (`docs/CLIENT_WIRE.md`), проектируется раньше любого графического клиента.
- **Приглашения — цепочка подписей.** Три роли: владелец узла, доверенный (может пригласить ограниченное число людей: по умолчанию 1, не больше 5), участник (общается, приглашать не может). Приглашение подписывает пригласивший и нумерует; узел хранит, кто кого привёл, и **считает** (подпись сама счёт не ограничивает); владелец может убрать человека вместе со всеми, кого тот привёл. Новое устройство подтверждает пригласивший по короткому коду; ссылка-приглашение одноразовая и недолговечная.
- Выход в интернет через узел для участника выключен по умолчанию: трафик уходит с адреса владельца узла, и отвечает за него владелец.
- Короткоживущие ключи (продление раз в сутки) для делегированных прав; у корневого ключа владельца есть путь восстановления.
- **Готово, когда:** приглашение сверх лимита и поддельное приглашение отвергаются (тест), отзыв каскадом работает.

### Фаза 6. Сеть узлов (L)
- Защита от массовых поддельных узлов (Sybil) и репутация по истории поведения.
- Распределённый поиск: починить и покрыть тестами запросы поиска значений (сейчас часть ответов только записывается в журнал), подписи записей должны покрывать адрес и возможности.
- **Готово, когда:** сеть из нескольких десятков узлов на тренировочном стенде находит записи и переживает отказ части узлов.

### Фаза 7. Эксплуатация (M)
- Сборки под Linux, Windows и macOS, установщик, юниты службы с минимальными правами.
- Усиленное размещение: узел в песочнице, порты закрыты и открываются только проверенным.
- Резервные копии ключей и данных.

### Фаза 8. Обновления (позже)
- Только подписанные готовые сборки, никогда сборка на узле.
- Откат при неудачном обновлении.

### Фаза 9. Мобильное приложение (после)
- Подключить к приложению пароль прокси и защищённое соединение по отпечатку сертификата (сейчас приложение отстаёт от узла).
- Ядро узла внутри приложения, чтобы телефон за NAT мог дойти до компьютера за NAT через ретранслятор.
