# Invariants: What Must Not Change

A short list of project promises. They protect the design from “improvements” that actually damage it. Rule: **change an invariant only through a separate owner decision**, never as part of work on another feature. Every invariant has a guard test; when a test does not exist yet, the table says so with a planned phase.

`tests/invariants.rs` checks this document itself: every `file::name` test reference must exist, and every invariant must have at least one such reference or a “waiting” note with a phase. The document cannot drift away from the tests.

| No. | Invariant | Status | Guard |
|---|---|---|---|
| I1 | All traffic between two nodes (messages, files, calls, and the core network) is encrypted with forward secrecy, using one-time keys for every handshake; unauthenticated plaintext is rejected; the receiver logs no plaintext packets. | yes, between two nodes | `tests/testnet_comms_test.rs::people_talk_and_send_files_only_over_encrypted_links`, `src/crypto/handshake.rs::handshake_secrets_are_not_kept`, `src/crypto/handshake.rs::two_handshakes_give_different_keys`, `src/netlayer/encryption.rs::two_handshakes_give_different_keys_so_old_traffic_stays_closed` |
| I2 | An intermediary node or relay cannot read content between people's devices through end-to-end encryption. | waiting — phases 3 and 5 | E4 protects paired devices; PC-to-PC chat uses YSE1 between owner nodes. A phone's own node reads plaintext sent to an ordinary remote contact. The stubs in `communication/encryption.rs` are not the active PC chat path. See `docs/PRIVACY.md`. |
| I3 | Keys, secrets, and passwords never enter logs. | yes | `tests/no_secrets_in_logs.rs::logs_never_contain_key_material` |
| I4 | Secret files are created private (`0600`) with no window in which other users can read them. | yes | `tests/private_files_guard.rs::secrets_are_never_written_loose_and_chmodded_later`, `src/util/private_file.rs::a_new_file_is_private_and_holds_the_data` |
| I5 | Foreign input bytes cannot crash the node: no panic, hang, or gigabyte allocation, either before the handshake (parsers and signed hellos with hostile fields) or after it (a hostile peer with a valid key sends every message type). | yes | `tests/robustness.rs::decoders_survive_hostile_bytes`, `tests/hello_adversarial_test.rs::hostile_but_signed_hellos_do_not_kill_either_hello_listener`, `tests/data_plane_fuzz_test.rs::a_hostile_peer_with_a_real_session_cannot_stop_the_node` |
| I6 | Replayed, forged, or corrupted packets are rejected. | yes | `src/crypto/session.rs::the_same_packet_is_refused_the_second_time`, `src/crypto/session.rs::a_changed_byte_a_changed_header_or_a_wrong_key_is_refused_and_does_not_hurt_the_window`, `tests/hello_replay_test.rs::replayed_hello_from_different_address_is_rejected` |
| I7 | The hello signature covers every field: an address or declared capability cannot be changed without the key. | yes | `src/netlayer/packet.rs::changing_any_single_field_breaks_the_signature` |
| I8 | The wire format does not change silently: session-packet bytes and signed-hello bytes are fixed by golden vectors confirmed by an independent implementation. | yes | `src/crypto/session.rs::golden_vector`, `src/netlayer/packet.rs::the_signed_bytes_are_frozen` |
| I9 | The node protects itself: forged identities cannot inflate the peer table. | partial | `tests/hello_flood_test.rs::a_flood_of_fresh_identities_from_one_address_does_not_fill_the_peer_table`, `tests/p2p_hello_flood_test.rs::p2p_flood_of_fresh_identities_is_limited_and_honest_nodes_still_get_in`; session, relay, and transfer limits are waiting, phase 2. |
| I10 | Multi-node circuits use layered encryption and a handshake signed by each node's key; a middle node cannot impersonate the next one; replayed or corrupted cells are rejected; cells have equal size. | yes | `src/hops.rs::a_middle_node_cannot_pose_as_the_next_one`, `src/hops.rs::replayed_and_tampered_cells_are_dropped`, `src/hops.rs::a_three_hop_circuit_is_built_and_data_travels_both_ways_but_only_the_exit_reads_it`, `src/hops.rs::the_same_cell_looks_different_on_every_link` |
| I11 | Internet exit through a node never opens the owner's computer or home network. | yes | `src/exit_policy.rs::the_exit_never_connects_to_this_computer_or_the_home_network`, `tests/invariants.rs::exit_handlers_use_exit_policy_only` |
| I12 | The owner decides who may exit through the node; the default is trusted devices only. | yes | `src/exit_policy.rs::who_may_exit_follows_the_owners_choice` |
| I13 | Management-page login backs off after failed attempts with increasing delay; the password is stored only as a hash. | yes | `src/web/auth.rs::backoff_actually_expires_after_waiting` |
| I14 | A packet number does not repeat under one key (counter plus random session salt); the key changes automatically without losing packets in flight. | yes | `src/crypto/session.rs::counters_never_repeat_and_start_at_one`, `src/crypto/store.rs::a_packet_sent_before_a_key_change_still_arrives_after_it`, `tests/testnet_rekey_test.rs::keys_are_replaced_in_a_running_network_without_losing_messages` |
| I15 | A client is invited only by the node owner or a trusted device within the limit; the invitation is signed and counted by the node. | waiting — phase 5 | The “client — node” protocol has not been written yet. |
| I16 | A circuit exit, which does not know the sender, opens web ports only; the owner's device is identified by a tag that only the secret owner can create. | yes | `src/hops_net.rs::only_web_ports_by_default`, `src/hops_net.rs::a_personal_request_carries_a_tag_only_the_owner_can_make` |
| I17 | Country lists, exit selection, and neighbor distribution use only cards whose reachability was proved by a signed reverse connection; an address change requires a new check. | yes | `src/network_offers.rs::only_cards_proved_by_a_connect_back_are_listed_gossiped_and_used_until_the_address_changes`, `src/reachability.rs::a_reachable_node_that_owns_its_key_is_verified_and_everyone_else_is_not` |
| I18 | An exit whose measured country differs from its claim, or from the country required by the owner, is excluded from selection. | yes | `src/exit_select.rs::a_measured_country_that_differs_from_the_claim_throws_the_exit_out_and_verified_ones_come_first` |
| I19 | The entry-node list is accepted only with the pinned key's signature; forgery, rollback, expiry, and extra fields are rejected. | yes | `src/bootstrap/mod.rs::a_signed_list_verifies_and_every_kind_of_tampering_is_refused`, `src/bootstrap/mod.rs::stale_and_rolled_back_lists_are_refused_but_a_newer_or_equal_one_is_taken`, `src/bootstrap/mod.rs::the_shipped_list_is_signed_by_the_pinned_key` |
| I20 | A client availability record is signed by its key; forgery cannot redirect the owner's devices, which look it up by the known key. | yes | `src/relay_net.rs::the_store_keeps_the_newest_record_per_key_and_the_asker_picks_by_the_key_he_knows` |
| I21 | The network is not called anonymous against a whole-network observer: that requires cover traffic and entry-node pinning. | waiting — phase 4 | Circuits exist (I10), but those two measures do not. |
| I22 | A node number belongs only to its key: it is derived from the signing key (hash plus `YB1` tag); hellos, cards, relay records, invitations, and entry-node lists whose number was not derived from the key are rejected everywhere, without a transition period because the network is new. A saved identity with a random number receives its derived number while retaining all keys. | yes | `src/util/types.rs::a_node_id_belongs_only_to_the_key_it_is_derived_from`, `src/network_offers.rs::a_bound_node_id_cannot_be_claimed_with_another_key`, `src/relay_net.rs::a_bound_node_id_cannot_be_claimed_with_another_key_in_a_via_record`, `src/netlayer/transport.rs::a_hello_claiming_a_bound_node_id_of_another_key_is_rejected`, `src/core/identity.rs::an_identity_saved_with_a_random_id_gets_its_bound_id_and_keeps_every_key` |
