# Bootstrap: как новый узел находит вход в сеть

В этой папке лежит **подписанный список входных узлов** — файл, к которому обращаются новые узлы при запуске.

| Файл | Что это |
|---|---|
| `bootstrap.json` | сам список: входные узлы (номер, ключ, адреса, страна, роли), срок действия, номер выпуска, подпись |
| `signer.pub` | открытый ключ подписи списка; он же вшит в программу (`src/bootstrap/mod.rs`, `SIGNER_KEYS`) |

Секретный ключ подписи **в репозитории не лежит и лежать не должен** (его создаёт владелец командой `yandi bootstrap keygen` и хранит у себя).

## Как это работает

1. При запуске узел скачивает `bootstrap.json` (по умолчанию с `raw.githubusercontent.com` этого репозитория; другой адрес — переменная `YANDI_BOOTSTRAP_URL`, можно несколько через запятую).
2. Проверяет: подпись закреплённым ключом, срок (`expires`), что номер выпуска (`sequence`) не меньше уже известного (защита от отката на старый список), форму файла (число узлов, адреса, ключи).
3. Сохраняет копию на диск (`bootstrap_cache.json` в папке данных): если источник недоступен, узел использует её.
4. Подключается к входным узлам. Для каждого проверяется, что по адресу отвечает узел с **тем самым ключом**, который записан в списке (подмена входного узла на чужой адрес не проходит).
5. Дальше узел живёт сам: карточки и обмен соседями. Локальный файл `nodes/bootstrap.json` (по желанию владельца узла) добавляется к подписанному списку и подписи не требует.

Что список **не** решает: кто может заблокировать источник (GitHub), закроет новичку вход. Поэтому есть копия на диске, второй адрес (`YANDI_BOOTSTRAP_URL`), приглашения со своими входными узлами и соседи, найденные раньше. Источник видит адрес каждого, кто его запрашивает.

## Как владельцу списка его менять

Ключ подписи списка **нигде не хранится в файле**. Он живёт только в закрытой среде вашего узла: выводится из ключа среды, появляется в памяти, когда вы открыли среду паролем, и стирается при запирании. Сид-фраза восстанавливает среду, а с ней и тот же ключ, отдельной резервной копии не нужно. Секрет наружу не выходит: узел сам подписывает список, вы получаете только подписанный файл.

```bash
# править список (без ключа): добавить узел по визитке со страницы узла или из ~/.yandi/node_card.txt
yandi bootstrap from-card bootstrap/bootstrap.json "$(cat ~/.yandi/node_card.txt)" --mobile ВНЕШНИЙ_IP:8444 --roles entry,relay,guest --region RU
# или вручную
yandi bootstrap add bootstrap/bootstrap.json --key <64 hex> --addr 203.0.113.10:9000 --region NL --roles entry,relay
# убрать узел
yandi bootstrap remove bootstrap/bootstrap.json --id <начало номера>

# один раз: узнать открытый ключ подписи (среда должна быть открыта: yandi admin vault unlock),
# записать его в bootstrap/signer.pub и пересобрать узел и приложение (ключ вшивается при сборке)
yandi admin bootstrap pubkey

# подписать (выпуск +1, срок +90 дней; просит админ-пароль) и проверить
yandi admin bootstrap sign bootstrap/bootstrap.json --days 90
yandi bootstrap verify bootstrap/bootstrap.json
```

Любая правка файла (`add`, `remove`, `from-card`) сбрасывает подпись; перед публикацией список нужно подписать заново. Подписанный файл публичный: его выкладывают на GitHub и сайт, а узлы и приложения проверяют подпись закреплённым открытым ключом.
